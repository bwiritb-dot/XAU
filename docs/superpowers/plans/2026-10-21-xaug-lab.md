# План: XAUG lab — перебор параметров обеих стратегий

## ИКР
Одна команда на ПК владельца → через ≈ 30 мин готов отчёт: какие переменные
реально двигают результат WSB A и Разворота B, как они влияют друг на друга,
какой набор лучший — и выживает ли он на 2 годах, которых подбор не видел.

## Что перебираем
Значение по умолчанию = оригинал (app.js). Диапазоны — 🟡, правятся до «го».

**WSB A — вход**
| Переменная | Оригинал | Диапазон |
|---|---|---|
| Период ATR | 14 | 7–28 |
| Доля тени от свечи | 45 % | 30–65 % |
| Тень против max(тело, другая тень) | 1,5× | 1,0–3,0 |
| Мин. размер свечи | 0,3 ATR | 0–0,8 |
| Окно бокса / мин. теней | 5 / 3 | 3–8 / 2–5 (теней ≤ окна) |
| Границы бокса | тела | тела · тени |
| Подтверждение пробоя | 1 закрытие | 1 · 2 закрытия |
| Жизнь бокса | 100 | 20–200 |

**Разворот B — вход**
| Переменная | Оригинал | Диапазон |
|---|---|---|
| Боллинджер период / σ | 16 / 3,9 | 10–40 / 2,0–4,5 |
| Отклонение от VWAP | 1,5 % | 0,5–2,5 % |
| AO быстрый / медленный | 4 / 96 | 3–10 / 34–150 |
| SMI быстрый / медленный / сигнал | 4 / 24 / 4 | 3–10 / 12–40 / 3–10 |
| UO периоды / порог | 12-24-48 / 40-60 | ×0,5–×2 / 25–45 (зеркально) |
| LRS период / порог | 7 / 3 | 5–20 / 1–6 |
| Окно взвода | 12 | 3–30 |
| Разворотов из 4 | 3 | 2–4 |

**Сделка — отдельно для каждой стратегии**
| Переменная | WSB | Разворот | Диапазон |
|---|---|---|---|
| Стоп | 1,5 ATR (или край бокса) | −1,0 % / +0,75 % | 0,5–3 ATR · 0,3–2 % |
| TP1 / TP2 / TP3 | 0,5 / 0,75 / 1,0 % | так же | 0,2–2 %, по возрастанию |
| Доли закрытия | 50 / 25 / 25 | так же | шаг 25 %, сумма 100 |
| Стоп после TP1 / TP2 | +0,04 / +0,5 % | так же | 0 – TP1 / 0 – TP2 |
| Лимит времени | 150 свечей | нет | 20–500 · нет |

**Не перебираем:** зона смерти, комиссия 0,04 % (торговля на XAUUSDT perp),
порядок «стоп раньше TP» внутри свечи, прогрев, «проценты» (на сделки не влияют).

## Шаги
1. **Данные** — `lab/fetch.mjs`: все месяцы PAXGUSDT и XAUUSDT 15m → `lab/data/*.json`,
   время приведено к миллисекундам. Ворота: дыр > 1 ч нет или все перечислены в отчёте.
2. **Движок** — `lab/engine.mjs`: обе стратегии с параметрами на входе; расчёт
   переписан из `XAUG-v2/src/core.js`. Ворота: с параметрами по умолчанию метки
   и PnL совпадают с core.js на 100 % (фикстура + 11 мес XAUUSDT).
3. **Скорость** — ворота: 6 лет за ≤ 2 с на один поток.
4. **Перенос PAXG → XAUUSDT** — на общих 11 мес: доля совпавших сигналов и сумма
   по обоим рынкам. Ворота: совпадение < 50 % → стоп, вопрос владельцу.
5. **База** — оригинальные параметры на PAXG по всем окнам.
6. **Optuna** — `lab/optimize.py`: в каждом окне по 2 000 прогонов на стратегию, только на
   2 годах подбора, процессов node = число потоков. Важность переменных (fANOVA — доля разброса
   результата, которую объясняет каждая переменная).
7. **Сетка** — 5 самых важных переменных × 5 значений = 3 125 прогонов на стратегию,
   остальные — лучшие из Optuna. Карты «переменная × переменная».
8. **Проверка** — оригинал / лучший Optuna / лучший сетки на 6 мес проверки каждого окна,
   склейка всех проверок в одну кривую + последние 11 мес на XAUUSDT. Стабильность:
   сколько окон подряд лучший набор остаётся похожим.
9. **Отчёт** — `lab/report.html`: таблицы, важность, карты пар, кривые капитала;
   `lab/README.md` — запуск на Windows одной командой.

Время ≈ 1 ч на i5-11400F, ≈ 3 ч в облаке (оценка: 8 окон × 2 стратегии × ≈ 5 000 прогонов × ≈ 0,5 с; замер — шаг 3).
RTX 3060 не нужна: прогон и так быстрый, перенос на видеокарту не окупится.

## Где живёт
- Новая папка `lab/` в корне. `XAUG-v2/` и оригинал не меняются.
- Код строится и проверяется в облаке на малом объёме; полный прогон — на ПК.
- Нужно на ПК: Node 20+, Python 3.11+, `pip install optuna`.

## Вопросы
1. Win rate без ограничений вырождается: TP1 0,2 % + стоп 3 % дают ≈ 90 % побед при
   минусе в сумме (Разворот уже сейчас: 65 % побед, −11,3 %). Победа = сделка с PnL > 0
   после комиссии. A — максимум win rate при сумме > 0 и ≥ 50 сделок за 2 года подбора,
   затем больше сделок; B — чистый win rate, затем сделки. Рекомендую A.
